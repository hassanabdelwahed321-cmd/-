# Azzam — نظام متابعة الشركات الأسبوعي

نظام عربي RTL يحافظ على طريقة الجدول الأسبوعي الموجودة في الصورة: مجموعتان للشركات، وصف لكل شركة، وأيام العمل من السبت إلى الأربعاء ثم الجمعة؛ يوم الخميس إجازة ولا يظهر في الجدول. التصميم تم تحديثه ليكون حديثاً وواضحاً على الكمبيوتر والموبايل.

## الوظائف
- جدول أسبوعي مع التنقل بين الأسابيع وزر «هذا الأسبوع» والطباعة.
- مجموعتا الشركات: «شركات الجرشين» و«شركات الشويك».
- كل مربع يوم يفتح تأكيدين مستقلين فقط: دخول الشركة للمخزن، واستلام ملف Excel.
- تسجيل الموظف والتاريخ والوقت تلقائياً في قاعدة البيانات.
- إضافة الشركات وحذفها (أرشفتها) متاحان لمدير النظام فقط.
- إشعارات عند إضافة شركة أو حذفها فقط؛ لا تصدر إشعارات عند تسجيل التأكيدات.
- صورة شخصية تُرفع إلى Supabase Storage مع فحص نوع الصورة وحجمها، وتُعرض دون تشويه.
- عند فتح قائمة الإشعارات يختفي عدّاد الإشعارات باعتبارها مقروءة، وتظل تفاصيل الإشعارات ظاهرة داخل القائمة. يظهر العدّاد مجدداً عند إضافة أو حذف شركة جديدة.
- إغلاق قائمة الإشعارات والملف الشخصي عند الضغط خارجها أو الضغط على Escape.

## التشغيل على جهازك
يتطلب Node.js 20 أو أحدث.

1. فك ضغط المشروع.
2. **احتفظ بملف `.env.local` الموجود عندك من مشروعك الأصلي وانسخه إلى مجلد المشروع الجديد**. لم أضعه داخل ملف التسليم لحماية مفاتيح الاتصال.
3. افتح PowerShell داخل مجلد المشروع وشغّل:

```powershell
npm install
npm run dev
```

لإنشاء نسخة إنتاج:

```powershell
npm run build
```

## تحديث قاعدة Supabase — مهم قبل الاستخدام

افتح Supabase Dashboard ثم SQL Editor وشغّل الملف:

`supabase/migrations/20261102_azzam_weekly_table_security.sql`

هذا التحديث يضيف جدول التأكيدات الأسبوعية وسجل إشعارات الإضافة والحذف، ويضيف مجموعات الشركات، ويشدد سياسات RLS. لا يحذف بيانات الشركات أو سجلات التأكيدات القديمة.

بعد تشغيل التحديث:
1. تأكد أن حساب المدير موجود في `auth.users` وله سجل في `public.profiles`.
2. من SQL Editor، غيّر دور حساب المدير إلى `admin` باستخدام UUID الخاص به:

```sql
update public.profiles
set role = 'admin'
where id = 'ضع-UUID-حساب-المدير-هنا';
```

3. الحسابات الأخرى تبقى `staff`، ولا يمكن للموظف ترقية نفسه من الواجهة.
4. أضف الشركات للمجموعتين من شاشة إدارة الشركات بعد تسجيل الدخول كمدير.

## الأمان
- لا تستخدم `service_role` في الواجهة ولا تضعه في `.env.local` الخاص بالواجهة.
- استخدم فقط `VITE_SUPABASE_URL` و`VITE_SUPABASE_ANON_KEY` (مفتاح anon/publishable).
- RLS يفرض صلاحيات القراءة والتسجيل، ويقصر إضافة/أرشفة الشركات وسجل أحداثها على المدير.
- لا يتم الاعتماد على إخفاء الأزرار في الواجهة كوسيلة حماية؛ قاعدة البيانات هي التي تفرض الصلاحيات.
- مجلد الصور `avatars` عام للقراءة لأن الصور الشخصية تظهر داخل النظام، لكن رفع/تعديل الصور مقيد بمجلد المستخدم نفسه.
- لا تشارك ملف `.env.local` أو أي مفاتيح اتصال في المحادثات أو الصور.

## ملاحظة عن بيانات النسخة الحالية
البيانات تُقرأ وتُكتب مباشرة في Supabase؛ لا توجد بيانات شركات تجريبية أو دخول تجريبي محلي. إذا لم يكن الاتصال مضبوطاً، ستظهر شاشة إعداد بدلاً من السماح بدخول وهمي.


## حل مشكلة شاشة «جاري تجهيز نظام عزّام»
إذا بقيت شاشة التحميل، فالنسخة المحدّثة تنهي الانتظار بعد 10 ثوانٍ وتعرض خطأ الاتصال بدلاً من التعليق بلا نهاية. تأكد من أن مشروع Supabase يعمل وأن `.env.local` يحتوي رابط المشروع ومفتاح anon/publishable الصحيحين، ثم أعد تشغيل `npm run dev`. إذا حذفت المستخدم القديم من Authentication وأنشأت مستخدماً جديداً، فالمستخدم الجديد له UUID مختلف؛ يجب أن يكون له صف في `public.profiles` بنفس UUID. لا تستخدم UUID الحساب القديم.
